## Before a public release

1. Review the implemented [app contract](app-contract-required.md), publish an authenticated app baseline/release, and review the exact source, migration and dependency provenance.
2. Establish the maintainer's actual jurisdiction, publisher type, recognized signing identity and official distribution repository; configure reviewed public trust roots. A timezone is not identity evidence.
3. Authorize disposable provider accounts, cost exposure and cleanup scope. Prove the no-GitHub fresh install, intended-owner OAuth, bounded health, wrong-account refusal, interruption/resume and credential removal with the real app.
4. Test a signed package on clean Windows profiles with/without WebView2, including keyboard/high-DPI/minimum-size layout and reopen after interruption. Inspect both signatures and timestamps.
5. Review current dependency findings and the complete evidence record, then update `qualification.json` with concrete evidence references. Do not change false fields simply to bypass packaging.

Optional targeted independent security review should inspect the native command boundary, release signing/rotation, database baseline and real intended-owner bootstrap. It complements these engineering checks; it does not replace them.
